# week2-attention

把注意力机制拆到能自己写出来的程度。**不是**再听一遍讲解，而是：公式 → 双循环实现 → 矩阵实现 → 数值等价 + 性能对比。

## 一句话直觉

> 每个位置都在问一个问题（Q），拿自己的问题去和所有位置的标签（K）比对，
> 谁跟我最相关就给谁高分，然后按分数把所有内容（V）加权求和。

`scores = QKᵀ/√d_k → softmax → 加权求和 V`。三行公式，对应代码里三个函数。

## 实验结果

本机实测（Python 3.13.6 / Windows，`python benchmark.py`，取 3 次最小值）：

| n | 循环版(ms) | 矩阵版(ms) | 加速比 |
|---|---|---|---|
| 64 | 11.60 | 0.07 | **173x** |
| 128 | 46.04 | 0.44 | 105x |
| 256 | 183.60 | 1.19 | 154x |
| 512 | 733.20 | 5.08 | **144x** |

两点观察：

1. **同一份数学，快的不是"算得更少"，而是"运算顺序不同"**：矩阵版把 512×512 次独立的 `np.dot` 调用合并成一次 `Q @ K.T`，交给底层 BLAS 做连续的向量化运算。Python 的解释器开销从 26 万次降到 1 次，这 144 倍里绝大部分是「省掉解释器」换来的，而不是「省掉计算」。
2. **n 从 64 涨到 512（8 倍），循环版耗时从 11.6ms 涨到 733ms（63 倍）**——注意不是 64 倍而是 63 倍，因为 n 很小时固定开销（数组分配、随机数）占比更大。这个平方关系就是长上下文贵的原因：上下文从 4K 涨到 32K，注意力计算量变成 64 倍。

## 三个必须能答的问题

1. **为什么要除以 √d_k？** 不除会怎样？
2. **mask 加在 softmax 之前还是之后？** 如果加在之后会出什么问题？
3. **为什么循环版和矩阵版结果必须完全一样？** 如果不一样，说明哪里错了？

<details>
<summary>参考答案（先自己想 10 分钟再看）</summary>

1. 点积是 d_k 个随机数相乘再相加，方差随 d_k 线性增长 → d_k=64 时点积数值分散在 ±8 个量级，
   softmax 会被推成接近 one-hot（只有最大那个位置有权重，其余≈0），
   梯度几乎为 0，训练不动。除以 √d_k 把方差拉回 ≈1，分布保持"软"。
2. 必须加在 **softmax 之前**（把不许看的位置置成 -1e9）。softmax 之后再置零，那一行权重和就不是 1 了，
   相当于凭空丢掉了概率质量，输出整体变小；而且 `0 * log(0)` 这类问题会让梯度出岔子。
3. 两者是同一个数学表达式的不同求值顺序。矩阵乘法只是把 Σ_j 交给 BLAS 做，
   所以结果应当逐元素相等（浮点误差 1e-9 内）。不相等通常意味着：
   缩放位置不同、mask 的 True/False 方向搞反了、或者 softmax 轴设错（按列而不是按行归一化）。
</details>

## 延伸（时间够再做，时间不够跳过）

- 多头（multi-head）：把 d 切成 h 份，每份单独算 attention 再拼接。分母是 h 个头而不是 1 个头。
- 加位置编码：attention 本身对顺序无感（打乱 token 顺序结果一样），所以需要位置信息。
  验证方法：把输入序列反过来，观察无位置编码时输出集合不变。
