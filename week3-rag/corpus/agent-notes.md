# Agent 学习笔记

## 什么是 Agent

普通调用是"问一句答一句"，一次请求一次响应。Agent 是让模型自己决定下一步做什么：它可以调用工具、读工具返回的结果、再决定要不要继续调用，直到任务完成。核心差别是**循环**和**决策**。

## ReAct 循环

ReAct 的意思是 Reasoning + Acting。每一轮模型先输出一段思考（Thought），再决定调用哪个工具（Action），拿到观察结果（Observation）后继续。循环到它认为可以给出最终答案为止（Final Answer）。

手写 ReAct 只需要三个部件：一个工具注册表（名字到函数）、一段能约束输出格式的 system prompt、一个最多循环 N 次的 while。难点不在代码，在于模型经常不听话：格式写错、无限调用同一个工具、工具报错后不处理。所以必须有最大轮数、格式校验、异常兜底。

## 工具调用

工具本质是函数加一段 JSON Schema 描述。模型不会真的执行代码，它只是输出"我想调用 search，参数是 keyword=xxx"，由你的程序去执行，再把结果作为一条新消息喂回去。

安全边界很重要：模型决定调什么，但**执行权在人手里**。删除文件、发邮件、扣款这类操作必须加人工确认，或者限定参数范围。

## 记忆

模型的上下文是有限的，所以"记住用户偏好"要靠应用层自己做。常见做法是：短期记忆放最近 N 轮对话，长期记忆把重要事实抽出来存进数据库，下次对话时检索回来。本质上和 RAG 是同一套东西——都是"把不在上下文里的信息，按需取回来"。
